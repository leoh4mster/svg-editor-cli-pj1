## 已确认的实现方向

- 使用 TypeScript、面向对象、字段封装和一类一文件。
- Command 是必需模式。CLI 的注册表根据命令名取得命令对象，命令通过统一入口执行。
- 领域模型不依赖终端、文件系统或 XML 库。应用层不依赖 CLI 或基础设施的具体实现。
- 第 2 阶段引入 Composite 的统一子节点、摘要、属性和遍历接口；第 3 阶段增加递归编辑语义，第 4 阶段实现层级与顺序调整。
- 图形类型只在图形工厂分派，命令名只在命令注册表分派；这两处按题目要求标注“待重构”。
- 第 3 阶段采用文档快照支持历史。图形通过多态返回独立副本，编辑会话在草稿上执行，成功后才切换当前文档及更新历史；先保证嵌套结构、节点顺序和删除内容能够准确恢复。每个历史项保存两份完整文档，空间成本随文档大小线性增长。
- `box` 及插件加载留给后续课程阶段，本次不实现。

## 第 1 阶段的接口约定

- `init` 默认 800×600；只给宽度时高度为 600；最多两个尺寸参数。
- `canvas` 无参数查询；两个参数修改；只给一个参数报错。
- 尺寸必须为有限正数。修改前完成全部校验，失败不改变当前文档。
- 参数解析支持双引号、引号和反斜杠转义；仅整行注释，参数中的 `#ffffff` 不被截断。
- 交互终端显示 `svg>`；管道输入不显示提示符；单条命令报错后继续处理下一行。
- 显示帮助不需要先初始化文档；需要文档的命令在未初始化时使用题目规定的错误信息。

## 第 2 阶段的接口约定

- `create` 提供六种内置类型，尾部支持 `in <containerId>`；必须先有文档及目标容器。
- ID 全文档唯一、大小写敏感，允许中文；禁止空值、空白和 C0 / DEL 控制字符。创建前验证整个候选子树，不允许部分挂接或只登记部分索引。
- 坐标可以为负数；所有数值必须有限；图形宽高、半径允许零，不允许负数；画布宽高仍必须为正数。
- 可选 `fill` / `stroke` 省略时不补写默认属性。文本保留中文、空格、引号和反斜杠。
- `tree` 显示画布及有序结构，内联几何摘要；`tree <id>` 只显示子树；`show <id>` 显示完整属性和父级。
- 文档持有根节点、全局 ID 与父级索引，负责挂接；图形子节点返回快照。已挂接图形具有文档归属，容器只接受持有文档私有令牌的结构修改，不能跨文档共享节点。格式化器只生成文本，不接触 CLI IO，也不按类型分派。
- 图形工厂在应用层转换参数；几何验证在领域层。`main.ts` 组装创建命令、工厂与格式化器。

## 第 3 阶段的接口约定

- `move` 接受有限增量；`scale` 只接受有限正倍数，同时缩放位置和尺寸，容器递归作用于子孙；不缩放 `stroke-width`，也不修改文本内容。
- `set` 的通用白名单为 `fill`、`stroke`、`stroke-width`，各类型再负责自身几何属性，文本另支持 `text`；白名单外统一报 `unknown attribute: <attr>`。尺寸、半径、描边宽度允许零但不允许负数。数值解析由领域 `NumericValue` 统一处理，应用层 `CommandArguments` 委托它，不产生领域到应用层的依赖。
- `set` 修改 `g` 的样式是设置该容器的属性，采用标准 SVG 继承语义，不覆盖子节点显式样式；`delete` 删除容器及全部子孙。
- `Shape.clone/moved/scaled/withAttribute` 返回独立、未归属的深拷贝。`SvgDocument` 的受控替换保留原父级及同级位置，并维护 ID、父级索引和归属；删除前完成校验。克隆通过多态创建图形，不增加按类型分派或字符串序列化。
- `EditCommand` 继承 `Command`，将成功编辑统一交给 `EditorSession.executeEdit`。会话先克隆草稿，在草稿上执行编辑，再复制提交结果并准备历史快照，全部成功后再提交当前文档和历史；即使递归编辑在后续子孙处溢出，原文档与历史也不改变。提交结果与回调草稿也相互隔离。
- 历史由 `application/history` 的 `HistoryEntry`、`CommandHistory` 管理；每个编辑保存执行前后快照，恢复时再克隆，禁止共享可变历史引用。`create` 也进入同一历史路径；`help/tree/show` 不记录历史。
- `undo` / `redo` 成功摘要以 `undone: ...` / `redone: ...` 表示原编辑；没有相应历史时分别报 `nothing to undo` / `nothing to redo`。撤销后只有成功的新编辑清空 redo，失败编辑和显示命令均保留分支。
- 成功 `init` 或修改 `canvas` 后清空两栈并禁用历史；此时两条命令均按题目原文报 `undo not allowed after io command`，直到下一次成功编辑。`canvas` 查询、失败的文档命令与显示命令不影响该状态。`read/save` 在第 5 阶段接入同一规则。
